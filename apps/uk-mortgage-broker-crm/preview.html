Client Fact-Find — Mortgage & Protection

Microsoft Forms template for UK residential and buy-to-let cases. Prefill case reference and invitation ID from the CRM invitation. Sterling figures. Review-first: submissions never silently overwrite verified facts.

Branching rules

  1. If Number of applicants = 1, hide every Applicant 2 and Applicant 2 income question.
  2. If Number of applicants = 2, show Applicant 2 identity and income blocks.
  3. If employment status is Employed (any), show employer name, time in role, basic, overtime, bonus, commission.
  4. If employment status is Self-employed / limited company / partnership, show trading name, years trading and three years of profit.
  5. If other income is blank or 0, hide the other-income notes question.
  6. If purpose starts with Purchase, show agreed purchase price.
  7. If purpose is Remortgage, Further advance or Product transfer, show remortgage reason.
  8. If Commitments = Yes, show the repeating commitments list.
  9. If Existing private insurance = Yes, show the private-policy repeater (child records).
  10. If Employer benefits = Yes, show the employer-benefit repeater (child records).
  11. If Mortgage-linked cover = Yes, show the mortgage-linked repeater (child records).
  12. If Accuracy or Privacy declaration = No, Microsoft Forms should end; the Process Submission flow also rejects the response.
  13. Selecting ‘None’ under schemes should clear other scheme choices (Forms branching or Power Automate normalisation).

4. Commitments

Regular outgoings that a lender will count. Capture each commitment as its own related record rather than a single text box.

Do you have any regular credit commitments, rent, or childcare costs we should record? Required

Type: Yes / No · Forms key: commitments.hasAny · CRM: flags.hasCommitments · overwrite-if-empty

Branching: Yes reveals the repeating commitments list.

Add each commitment Required

Type: Repeating section · Forms key: commitments.items · CRM: commitments[] · create-child

Child records:

  • Type of commitment → commitments[].type
  • Lender / provider → commitments[].lender
  • Monthly payment (£) → commitments[].monthly
  • Approximate balance outstanding (£) → commitments[].outstanding
  • To be repaid on completion? → commitments[].toBeRepaid

Branching: Shown when the previous answer is Yes. Each row becomes a related Commitment record.

Power Automate

CRM - Process Client Fact-Find Submission

  1. When a new response is submitted (Microsoft Forms)
  2. Get response details
  3. Validate case reference and invitation ID
  4. Create staged / immutable submission record
  5. Map responses into CRM fields (review-first)
  6. Create related policy and employer-benefit records
  7. Hold proposed changes for review
  8. Create adviser-review and evidence tasks
  9. Update fact-find status
  10. Send client acknowledgement
  11. Record audit event

CRM - Process Inbound Client Email

  1. Office 365 Outlook: When a new email arrives in a shared mailbox (V2)
  2. Normalise sender address
  3. Match against Applicant 1 and Applicant 2 emails
  4. One match: auto-link · none: unmatched task · many: manual case selection
  5. Joint applicant: match both · forwarded: do not assume original sender is the client
  6. Changed email address: hold for verification
  7. Add to communication history
  8. Retrieve latest five communications
  9. AI extracts updateSummary, conversationSummary, proposedFacts, actions, replyDraft, requiresManualReview
  10. Proposed facts go to the adviser-review queue
  11. Draft reply for the adviser to send
